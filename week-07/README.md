## 1. GHC и GHCi

Haskell е компилируем език. Компилаторът се казва GHC. `ghc file.hs` прави изпълним файл, но за това във файла трябва да има `main`, главната процедура, откъдето програмата започва. Как изглежда е описано по-долу.

Типовете се проверяват при компилация, преди програмата да тръгне. Затова грешка в типовете спира всичко, дори ако е на ред, до който програмата още не е стигнала.

На упражненията ползваме GHCi, интерактивната среда на GHC. Тя зарежда файла и ни позволява да викаме функциите една по една, без `main`. Файлът е `.hs`.

| Команда | Какво прави |
|---|---|
| `ghci week7.hs` | зарежда файла, пуска се от терминала |
| `:r` | презарежда файла след промяна |
| `:t израз` | показва типа на израза |
| `:q` | изход |

Коментарите са с `--` до края на реда.

### `main` и `IO`

```haskell
double :: Int -> Int
double x = 2 * x

main :: IO ()
main = do
  print (double 21)
  putStrLn "done"
```

След `ghc file.hs` изпълнимият файл отпечатва `42` и `done`, всяко на нов ред.

- `IO a` е тип на входно/изходна операция, която връща стойност от тип `a`. `main` е такава операция.
- `()` е типът Unit и единствената му стойност също е `()`. `IO ()` е операция, която има само страничен ефект, например печатане, и не връща полезна стойност. Това е като `void` в C++ и Java.
- `do`-нотацията изпълнява няколко операции една след друга. `print` отпечатва стойност, а `putStrLn` отпечатва низ.
- Обикновена функция като `double` не може да печата. Типът ѝ `Int -> Int` казва, че тя само смята, а печатането става само в `IO`.

`main` трябва да е от тип `IO` нещо и най-често е `IO ()`. `main :: IO Int` също се приема, но върнатата стойност се игнорира. `main :: Int` е грешка при компилация: `Couldn't match expected type 'IO t0' with actual type 'Int'`.

`IO` и `do`-нотацията се разглеждат подробно в лекция 14. Засега ви трябва само това, за да компилирате програма.

## 2. Функции и типове

Как се дефинира функция:

```haskell
име :: Тип1 -> Тип2 -> Резултат   -- декларация на типа, по желание
име параметър1 параметър2 = израз   -- уравнение
```

```haskell
square :: Int -> Int
square x = x * x

add :: Int -> Int -> Int
add x y = x + y
```

Първият ред декларира типа на функцията: `add` приема два `Int` и връща `Int`. Последният тип е резултатът. Типът не е задължителен, но го пишете, защото така грешките се хващат по-рано. Повече за това има в раздел 3.

При повече аргументи е същото: `тип1 -> тип2 -> ... -> типN -> резултат`. Всички типове преди последния са аргументите по ред, а последният е резултатът.

```haskell
isTriangle :: Int -> Int -> Int -> Bool
isTriangle a b c = a + b > c && a + c > b && b + c > a
```

```haskell
isTriangle 3 4 5   -- → True
isTriangle 1 2 5   -- → False
```

Защо последният тип е резултатът? Вижте какво става, когато аргументите се подават един по един:

```haskell
add     :: Int -> Int -> Int
add 2   :: Int -> Int        -- един аргумент: остава функция, която чака още един
add 2 3 :: Int               -- два аргумента: остава само резултатът
```

Всеки подаден аргумент „изяжда“ една стрелка отляво. Когато подадете всички, остава последният тип, тоест резултатът. Затова правилото работи.

В Haskell всяка функция всъщност приема точно един аргумент, а „функция на два аргумента“ е функция, която взема първия и връща функция, която чака втория. Затова `Int -> Int -> Int` означава `Int -> (Int -> Int)`: `->` групира отдясно и тези скоби не се пишат. Затова може да подадете и само част от аргументите, като с `curry` в [седмица 4](../week-04/README.md):

```haskell
add5 :: Int -> Int
add5 = add 5
```

```haskell
add5 10          -- → 15
```

Извикването е без скоби и запетаи. Скобите само групират:

```haskell
add 2 3          -- → 5
square (2 + 1)   -- → 9
square 2 + 1     -- → 5. функцията се прилага преди +
add (-3) 5       -- → 2. отрицателното число е в скоби
```

Без скобите `add -3 5` е грешка, защото Haskell го чете като изваждане.

### Как Haskell разбира кое е функция

Име от букви, като `mod`, `div` или `square`, е функция и се пише преди аргументите си. Някои функции са специални символи, като `+`, `==` и `&&`. Те се използват като оператори: между аргументите си, а не преди тях.

Прилагането на функция е с по-висок приоритет от всеки оператор. Затова скоби около функцията не трябват:

```haskell
mod 12 3 == 0      -- → True. чете се като (mod 12 3) == 0
```

| Haskell | C/C++ |
|---|---|
| `f a + g b` | `f(a) + g(b)` |
| `f (a + g b)` | `f(a + g(b))` |

Скоби трябват, когато аргументът е израз, а не просто име или число:

```haskell
mod (12 + 3) 10    -- → 5
```

`mod 12 + 3 10` е грешка, защото се чете като `(mod 12) + (3 10)`.

Прилагането на функция е ляво асоциативно: `f x y` е `(f x) y`. Това е същото като `add 5` по-горе: `add`, приложено към `5`, дава функция, която после се прилага към втория аргумент.

Двете роли могат да се разменят. С обратни апострофи всяка двуаргументна функция се записва инфиксно, а със скоби операторът става обикновена функция:

```haskell
12 `mod` 5         -- → 2. същото като mod 12 5
(+) 2 3            -- → 5. същото като 2 + 3
```

Типовете, които ще ви трябват:

| Тип | Какво е |
|---|---|
| `Int` | цели числа (signed, 64 бита) |
| `Integer` | дълги цели числа, без ограничение |
| `Double` | дробни числа |
| `Bool` | булеви стойности: `True` или `False` |

### `Int` или `Integer`

`Int` заема фиксирано място, 64 бита, като `long long` в C++. Най-голямата му стойност е `maxBound`. Ако резултатът я надмине, грешка няма, а числото тихо се превърта:

```haskell
maxBound :: Int            -- → 9223372036854775807
(maxBound :: Int) + 1      -- → -9223372036854775808
2 ^ 64 :: Int              -- → 0
2 ^ 64 :: Integer          -- → 18446744073709551616
```

`Integer` е за дълги цели числа, без ограничение, но е по-бавен. Ползвайте `Integer`, когато числата растат бързо, като при факториел и Фибоначи. Затова `fact` по-долу е с `Integer`.

Двата типа не се смесват: `Int` и `Integer` не може да се съберат директно. Преобразуването е с `fromIntegral`, както от `Int` към `Double`.

`fromIntegral` се слага на стойността, чийто тип искате да смените. Тя взема цяло число, `Int` или `Integer`, и го превръща в типа, който е нужен там, където се ползва. Целевият тип не се пише, GHC го определя от другата страна на операцията:

```haskell
fromIntegral :: (Integral a, Num b) => a -> b   -- от цял тип a към произволен числов тип b
```

## 3. Извеждане на типове

Декларацията на типа не е задължителна. Компилаторът може сам да изведе типовете за повечето програми и без декларация извежда най-общия възможен тип:

```haskell
add x y = x + y      -- изведен: add :: Num a => a -> a -> a
half n = n / 2       -- изведен: half :: Fractional a => a -> a
isBig n = n > 100    -- изведен: isBig :: (Ord a, Num a) => a -> Bool
```

`Num a =>` значи „за всеки числов тип `a`“. Затова `add 2 3` дава `5`, а `add 2.5 1` дава `3.5`. Ограничението идва от операциите в тялото: `+` изисква `Num`, `/` изисква `Fractional`, `<` и `>` изискват `Ord`, `==` изисква `Eq`, а число като `100` изисква `Num`. Тези ограничения с класове се разглеждат в лекция 10.

Защо все пак декларацията се пише:

- **По-лесни грешки:** грешките в типовете се откриват по-лесно и се съобщават там, където сте сгрешили.
- **Четимост:** кодът се чете и разбира по-лесно.
- **Изискване на задачата:** понякога условието иска конкретен тип. Задачите за седмица 8 например дават `incrementAllBy :: [Int] -> Int -> [Int]`.
- **По-общ тип:** без декларация може да получите по-общ тип от този, който искате, например `Num a => ...` вместо `Int`.

## 4. Аритметика

```haskell
10 / 4          -- → 2.5. деление на дробни
div 10 3        -- → 3. частно при целочислено деление
mod 10 3        -- → 1. остатък при целочислено деление
10 `mod` 3      -- → 1. същото, записано инфиксно
even 10         -- → True
odd 10          -- → False
```

`/` с `Int` е грешка. Ако имате `Int`, а искате дробен резултат, преобразувайте цялото число в реално с `fromIntegral`:

```haskell
half :: Int -> Double
half n = fromIntegral n / 2
```

```haskell
half 5          -- → 2.5
```

Изрази, които ще ви трябват често:

```haskell
mod n d == 0    -- d дели n
mod n 10        -- последната цифра на n
div n 10        -- n без последната цифра
```

## 5. Сравнения и логика

```haskell
3 == 3              -- → True
3 /= 3              -- → False. „различно“ е /=, не !=
3 <= 5 && 5 <= 7    -- → True. конюнкция (и)
3 > 5 || 5 > 4      -- → True. дизюнкция (или)
not True            -- → False. отрицание
```

## 6. Условни изрази и условия (guards)

```haskell
absolute :: Int -> Int
absolute x = if x < 0 then -x else x
```

В Haskell `if` е израз и има стойност, затова клаузата `else` винаги е задължителна.

При повече случаи вместо вложени `if` се ползват условия (guards). Всяко условие е булев израз, наречен „охраняващ“ израз. Условията са като `cond` в Racket: оценяват се отгоре надолу и печели първото с оценка `True`, а `otherwise` е като `else`.

```haskell
sign :: Int -> Int
sign x
  | x > 0     = 1
  | x == 0    = 0
  | otherwise = -1
```

```haskell
absolute (-4)   -- → 4
sign (-4)       -- → -1
```

Забележка: клаузата `otherwise` не е задължителна. Ако обаче нито едно условие не е вярно, програмата спира с грешка `Non-exhaustive patterns`.

## 7. Съпоставяне с образец (pattern matching)

Дефиницията на функция може да се състои от няколко уравнения. Уравненията се съпоставят по ред с аргументите, докато се намери подходящо, затова конкретните стойности са най-отгоре:

```haskell
fact :: Integer -> Integer
fact 0 = 1
fact n = n * fact (n - 1)
```

```haskell
fact 5          -- → 120
```

Образците работят и за списъци. `[]` е празният списък, а `(x:xs)` разделя непразния на глава `x` и опашка `xs`, като `first` и `rest` в Racket. Специалният символ (wildcard) `_` съответства на всичко и се ползва, когато стойността не ни трябва. Типът `[Int]` е списък от `Int`.

```haskell
mySum :: [Int] -> Int
mySum []     = 0
mySum (x:xs) = x + mySum xs

myLength :: [Int] -> Int
myLength []     = 0
myLength (_:xs) = 1 + myLength xs
```

```haskell
mySum [1, 2, 3]       -- → 6
myLength [5, 7, 9]    -- → 3
```

Скобите около `x:xs` са задължителни. Без тях Haskell чете `mySum x:xs` като `(mySum x):xs` и дава `Parse error in pattern`.

## 8. Рекурсия и итеративен процес

Обхождане на интервал с условия (guards), като рекурсивен процес:

```haskell
sumSquares :: Int -> Int -> Int
sumSquares a b
  | a > b     = 0
  | otherwise = a * a + sumSquares (a + 1) b
```

```haskell
sumSquares 1 3  -- → 14
```

При итеративния процес резултатът се натрупва в допълнителен аргумент на помощна функция, като в Racket. Помощната функция може да е локална дефиниция, с `where` или с `let ... in`, или отделна функция. Примерът и при трите е факториел. Имената са различни, за да могат и трите да стоят в един файл.

### С `where`

Клаузата `where` добавя локални дефиниции към дефиницията на функцията, след тялото ѝ, като вложения `define` в Racket. Това е най-четимият начин.

```haskell
factIter :: Integer -> Integer
factIter n = helper n 1
  where
    helper 0 acc = acc
    helper k acc = helper (k - 1) (acc * k)
```

### С `let ... in`

`let ... in` е израз. Прави същото като `where`, но локалните дефиниции са преди тялото.

```haskell
factIter2 :: Integer -> Integer
factIter2 n =
  let helper 0 acc = acc
      helper k acc = helper (k - 1) (acc * k)
  in helper n 1
```

При `where` и при `let` помощната функция вижда аргументите на основната.

### С отделна функция

Помощната функция е отделна дефиниция във файла. Вижда се от целия файл, но не вижда аргументите на основната функция, затова всичко ѝ се подава изрично.

```haskell
factHelper :: Integer -> Integer -> Integer
factHelper 0 acc = acc
factHelper k acc = factHelper (k - 1) (acc * k)

factIter3 :: Integer -> Integer
factIter3 n = factHelper n 1
```

```haskell
factIter 5      -- → 120
factIter2 5     -- → 120
factIter3 5     -- → 120
```

### Още един пример с `where`

С цифрите на число:

```haskell
sumDigits :: Int -> Int
sumDigits n = helper n 0
  where
    helper 0 acc = acc
    helper k acc = helper (div k 10) (acc + mod k 10)
```

```haskell
sumDigits 1234  -- → 10
```

Редовете с условията и под `where` трябва да са отместени надясно, иначе Haskell не ги смята за част от функцията. Неотместените условия дават грешка, а неотместената помощна функция става отделна функция за целия файл и вече не вижда аргументите на основната.

## 9. От Racket към Haskell

| Racket | Haskell |
|---|---|
| `(define (f x y) ...)` | `f x y = ...` |
| `(f x (+ y 1))` | `f x (y + 1)` |
| `(quotient n 10)`, `(remainder n 10)` | `div n 10`, `mod n 10` |
| `(= a b)`, `(not (= a b))` | `a == b`, `a /= b` |
| `(and p q)`, `(or p q)` | `p && q`, `p \|\| q` |
| `#t`, `#f` | `True`, `False` |
| `(odd? n)` | `odd n` |
| `(cond [...] [else ...])` | условия (guards) с `\|` и `otherwise` |
| вложен `define` за помощна функция | локални дефиниции с `where` или `let ... in` |
